# SpaceCube (空间方块) — 产品设计文档

- Status: Approved (product design), pre-implementation
- Date: 2026-08-05
- Related: [AGENTS.md](../../../AGENTS.md) — 已落地的窗口结构与工程记录

## 1. 产品定位

一款在 PICO Swan 上运行的空间俄罗斯方块小组件。定位为**和系统其他窗口共存的空间小组件**
(类似 visionOS 风格的窗口化多任务)，不是独占沉浸式 VR 游戏。玩家可以在自己房间里打开一个
悬浮的游戏方块井，边玩边保持对周围环境和其他窗口的感知。

## 2. 技术选型记录(回顾此前讨论)

在产品设计之前，已经讨论并确定了技术路线，记录如下：

- **候选方案**：原生 PICO Spatial SDK(Kotlin + Jetpack Compose + SpatialUI) vs Unity。
- **决策**：选择**原生 PICO Spatial SDK**。
- **理由**：产品定位是"和系统其他窗口共存的空间小组件"，而不是独占式沉浸 VR 游戏。Unity
  应用通常以独占沉浸模式运行，难以接入 PICO Swan 的窗口化多任务体系；原生 Spatial SDK 官方
  就是为"Planar 入口窗口 + Volumetric 功能窗口"这种模式设计的，`WindowContainer` /
  `LocalSpatialNavigator` 等 API 天然支持该场景，`pico-cli project create --template planar`
  也直接提供了对应脚手架。
- **备选场景说明**：如果产品方向改为完全沉浸式、独占式的 VR 游戏(不需要和其他窗口共存)，
  Unity 成熟的物理/动画/粒子工具链会更合适、迭代更快——但这不是当前产品的定位，仅作为
  未来若方向变化时的备选记录。
- **已落地的工程结构**：Planar `DefaultWindowContainer`(HomePage) + Volumetric
  `WindowContainer(id = "GameWindow")`，通过 `navigator.openWindowContainer` /
  `closeWindowContainer` 互相导航。详见 [AGENTS.md](../../../AGENTS.md)，本文档不重复
  记录工程细节，只引用。

## 3. 核心玩法规则

玩法本质是**经典 2D 俄罗斯方块规则**，用一个有真实厚度的体积盒子来呈现：

- **网格**：X-Y 平面网格，宽 8 × 高 14。Z 方向(深度)固定为一层，不参与摆放判定——
  也就是说不存在独立的第三个摆放轴，避免了三维深度对齐的认知负担。
- **方块**：标准 7 种俄罗斯方块(I / J / L / O / S / T / Z)，随机分发使用标准
  **7-bag** 算法(每 7 个一组，包含全部形状各一次，组内顺序随机)，避免连续出现同一
  形状。渲染为有真实厚度的立体方块组合(体积视觉，非纯平面贴图)。
- **消行**：单行填满即消除，经典判定与计分逻辑(消除行数越多单次得分越高，具体分数
  表在实现阶段定义)。
- **游戏结束**：新方块的生成位置被已堆叠方块占用(顶部堵住)时结束。

## 4. 移动与旋转(交互手势)

- **移动**：裸手手势拖拽——手在水平方向的移动量映射为方块左右位移；手向下拖拽的
  动作映射为加速下落(拖得越低/越快，下落越快；松手或收回手势后恢复正常下落速度)。
- **旋转**：捏合/点击触发，绕 Z 轴 90° 旋转(即经典的平面内旋转)，与移动手势分离，
  避免和拖拽方向产生冲突/歧义。
- **备用输入**：控制器 ray + trigger，作为手势识别不稳定时的备用方案，移动/旋转
  语义与手势一致。

## 5. 下落速度与难度曲线

- **开局难度预设**：慢 / 中 / 快三档，作为整场基础下落速度。
- **消行自动加速**：随着消除的行数累计，下落速度按经典升级曲线自动提升，难度随时间
  推进。
- 两者叠加：难度预设决定起点，自动加速决定曲线走向。

## 6. 空间呈现与窗口模型

> **2026-08-06 更新(第一次)**：原先"Planar 入口窗口 + 点击后打开 Volumetric
> 游戏窗口"的双窗口方案，已按用户明确要求合并为单一窗口。双窗口方案的历史记录
> 仍保留在 §2 的技术选型记录中。
>
> **2026-08-06 更新(第二次，当前状态)**：实机测试发现 Volumetric 窗口自带的
> 跟随视线的标题栏(caption bar，含移动/最小化控件)会持续拦截拖拽/点击手势，
> 导致核心操作(拖拽移动、点击旋转)不可靠。用户明确要求"改为全沉浸式"并确认
> "改成 Stage 全沉浸"，因此当前实际结构已从 Volumetric `WindowContainer` 迁移为
> `Stage`(`StageStyle.Mixed`，透视背景仍可见，无需自定义天空盒)。这意味着
> §2 中"和系统其他窗口共存，而非独占沉浸"这一原因**已不再适用于当前实现**——
> 为了让核心手势操作可靠，产品放弃了"空间小组件与其他窗口共存"的最初定位，
> 改为全沉浸式独占体验。§2 的技术选型记录本身保留不改，作为历史决策记录。

- **单一全沉浸 `Stage` 默认容器**：应用启动直接进入全沉浸空间(通过
  `AndroidManifest.xml` 的 `pico.spatial.stage.id` + `pico.spatial.stage.style="1"`
  声明为 `StageStyle.Mixed`)，没有窗口边框/标题栏，不再有单独的 Planar 入口窗口，
  也不再是 Volumetric 窗口。
- **开始画面(沉浸空间内状态，非独立窗口)**：进入沉浸空间后先显示"空间方块"标题、
  历史最高分、慢/中/快难度选择、"开始游戏"按钮。点击"开始游戏"后立刻在**同一个
  沉浸空间**内开始游戏(不再是"打开另一个窗口")，游戏内 UI(计分、下一方块预览、
  拖拽区、暂停按钮)在开始前不显示。
- **走近查看的立体厚度感**：玩家仍可以走近/绕到旁边查看方块的立体厚度感——虽然
  深度不参与摆放判定，但视觉上是完整的立体呈现，这仍是本产品区别于普通屏幕
  俄罗斯方块的核心卖点。
- **落点投影(ghost piece)**：显示方块下落后最终会停留的行/列位置，用途是经典 2D
  玩法里的常规下落对齐辅助(不是为了解决三维深度歧义，因为本版本没有独立深度轴)。
- **下一方块预览**：井旁边悬浮一个 `AttachmentPanel`，显示下一个即将下落的方块形状。
- **暂停/继续**：点击暂停按钮呼出浮层菜单，暂停期间可查看当前堆叠状态，
  不计时、不下落。
- **音效/音乐**：下落、着地、消行、结束音效(已实现)；背景音乐因缺少音频素材
  文件暂未实现。
- **结束流程**：窗口内弹出 Game Over 浮层，显示本局分数，提供"返回开始画面"
  (回到同一窗口的开始状态，不是切换窗口)和"再来一局"两个操作。返回开始画面后
  展示历史最高分(本地持久化)。

## 7. 视觉风格

- **糖果 / 极简彩色**：方块使用高饱和度、圆角化的糖果色配色，替换掉当前项目模板
  自带的科幻风 `sci_fi_box` 素材(不采用科幻风)。
- **井体**：半透明浅色网格线框，配合 PicoTheme 暗色背景，让彩色方块在全沉浸空间里
  更醒目突出。
- 所有 2D UI(按钮、面板、浮层)遵循项目既有的 SpatialUI-only 规范(见 AGENTS.md)，
  不引入 Material/Material3。

### 7.1 视觉概念图

已产出一版视觉概念草图并获认可：[空间方块 · 视觉概念图](https://claude.ai/code/artifact/9df20452-3b23-4f4a-ba7a-09831809912b)。
草图确认了以下具体呈现方式，供实现阶段参考：

- **7 种方块的糖果配色参考值**：I 天蓝 `#52D1E8`、O 柠檬黄 `#FFD24C`、T 泡泡糖粉
  `#FF6FA0`、S 薄荷绿 `#57E0A0`、Z 樱桃红 `#FF5D5D`、L 橘橙 `#FFA23C`、
  J 葡萄紫 `#8B93F8`。每个方块用左上高光 + 右下阴影的斜切内阴影表现立体厚度感，
  而不是纯平色块。
- **落点投影(ghost piece)** 用同色虚线描边的空心方块表示，叠加显示在方块最终会
  停留的行/列位置。
- **下一方块预览** 是贴在井侧边的小悬浮面板，展示下一个形状的迷你网格。
- **即将消除的整行** 用发亮描边/高光强调(而不是变色)，提示玩家这一行已经填满。
- **分数 HUD** 悬浮在井的左上角，等宽数字字体，配合暗色玻璃底板。
- 井体本身在视觉上带轻微 3D 倾斜悬浮效果，呼应"可走近/绕到旁边看的真实体积盒子"
  这一核心卖点；HomePage 卡片则是更轻量的浅色平面卡片，两者形成明显的视觉层级差异。

## 8. MVP 范围边界

**包含(v1)**：

- 8×14 井 + 立体厚度呈现
- 7 种方块，7-bag 随机分发
- 手势横移 + 下拉加速下落，点击 Z 轴旋转，控制器备用输入
- 难度预设 + 消行自动加速曲线
- 单行消除计分，顶部堵住结束
- 下一方块预览、落点投影、暂停/继续菜单、音效与背景音乐
- 本地高分持久化，HomePage 展示上一局分数与历史最高分

**明确排除(v1 不做)**：

- 真三维深度摆放 / 多层横切消除
- X / Y 轴旋转(仅支持 Z 轴)
- 独立的硬降(hard drop)按钮(已由"下拉手势加速"覆盖，不需要额外控件)
- 多人 / 联机对战
- 云端排行榜(仅本地高分)

## 9. 后续演进方向(不在本次范围内，仅记录方向)

- **V2 关卡系统**：计划在 v1 上线后引入关卡机制，具体形式(不同井形 / 障碍物 /
  目标式通关 vs 无限生存等)留待 V2 单独开一轮设计讨论，此处仅作方向占位。
- 其余可能方向(优先级低于关卡，暂不展开)：多人对战、云端排行榜、更多视觉主题皮肤。
